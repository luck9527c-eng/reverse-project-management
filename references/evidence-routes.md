# 证据驱动与路线管理

## 结论的证据契约

| 标签 | 内容要求 |
|---|---|
| 观察事实 | 直接看到什么；目标 ID/哈希、运行 ID、原始文件链接与行号/时间/事件号/偏移 |
| 推断 | 支持证据、推理、替代解释、适用范围；置信程度有理由，不编造百分比 |
| 假设 | 可验证主张、预期观察、能推翻它的条件 |
| 未知 | 缺少什么、怎样获取、影响哪条路线或哪个结论 |

一条可审计链：**结论 → 路线 → 运行记录 → 原始文件及定位 → 目标与脚本/工具身份**。派生摘要额外引用生成步骤和父文件哈希。

工具输出、反编译结果和搜索命中分别记录来源及局限。空搜索只支持“在指定范围和条件下没有命中”。MCP 返回证据 ID 时保存原 ID、服务/版本及原始响应；会话可能失效时同步导出可持久化内容。

相反证据并列保存，写清冲突可能来自版本、配置、覆盖率还是解释。未能解释的冲突按 [证据争议](acceptance-audits.md#矛盾证据与有争议结论) 登记为 open，使 INDEX 标记受影响路线；暂停把争议结论当作可靠依赖或验收依据。新证据出现后修订推断，保留先前结论及修订原因。同一采集的不同导出按 [来源链](acceptance-audits.md#证据来源链) 去重，不按文件或工具数量累计独立验证。

## 路线记录

复制 [route.json](../assets/route.json) 为 `re/routes/R-001.json`，按实际情况填写：

- `question` / `hypothesis`：要减少的具体不确定性，以及可检验主张。
- `target_ids`：绑定 targets.json 中的不可变目标身份；不同目标的证据不能直接互换。
- `depends_on`：必须先验证成功的路线 ID；外部条件写 `prerequisites`。前置路线证死时评估依赖假设，把受影响路线置为 blocked 或修订，避免沿失效前提继续。
- `condition_ids` / `condition_reviews`：关键共享条件的引用与逐版本复查记录；按 [跨路线复查](cross-route-review.md) 管理。条件变化会触发关联路线及下游复查，包含已证死路线；原结论仍保留其范围。
- `experiment`：最小动作、需要观察的范围和结果、反证条件。`budget`：本轮可花的时间/次数/成本及停止条件。
- `evidence`：运行 ID，兼有支持和反对证据；同一目标范围内可引用其他路线的运行，保留原归属；读者沿 run.json 找到原始记录。
- `history`：每次状态变更的时间、from/to、原因和证据。首次状态 from 为 null；后续追加，末状态与 status 一致。
- `closure`：终结状态所需的结论、证据与边界；尚未终结时为空。

优先选能区分竞争解释、依赖已满足、可短时反馈的实验。一次只激活可实际管理的路线数，默认一条；同时推进时记录负责人和资源归属。

## 路线状态

| 状态 | 判定门槛 | 下一步 |
|---|---|---|
| planned | 具体问题、假设、实验与预算已记录 | 满足前提后进入 active |
| active | 当前正在推进的最小实验已明确 | 获取证据或记录阻塞 |
| blocked | 缺必要工具、权限、样本、依赖或观测能力；写解除条件 | 条件恢复后重开 active |
| paused | 预算耗尽或优先级下降；写暂停原因和恢复条件 | 有新预算或收益变化时恢复 |
| validated | 实验支持预先声明的成功判据；写适用目标、范围、局限与证据 | 作为已满足的依赖或交付结论 |
| falsified | 在明确范围内，可靠证据满足预先声明的反证条件 | 保存证死范围及重开条件 |
| superseded | 被明确的新路线替代或问题已失去必要性；链接替代路线与原因 | 沿替代路线继续 |

`validated` 证明该路线的验收判据达到，不代表整个项目完成。`falsified` 表示具体假设在限定条件下被否定，不宣称所有未来版本和配置永远无效。

状态可按事实转换；终结状态重新进入 active/planned 时，history 写明新证据、目标或前提变化，旧 closure 保留在对应历史条目的 `prior_closure` 中，再清空当前 closure。目标发生变化时通常新建路线，引用旧路线作为来源。

## 证死门槛

只有以下项目均可用证据说明，才填写 `status: falsified`：

1. **身份**：证据针对的目标哈希、版本和关键配置与路线一致。
2. **判据**：反证条件预先声明，本次结果实际满足该条件。
3. **观测链**：工具正确运行、目标动作实际触发、窗口与采样覆盖足够；正向对照或独立校验能说明本应看见的现象确实可见。
4. **局限**：明确排除了哪些解释，哪些未覆盖；连接失败、位数错误、权限不足、被截断的输出分别作为阻塞或证据缺口处理。
5. **闭合记录**：closure 包含 `summary`、`scope`、`criterion`、`coverage`、`control`、`limitations`、`reopen_when`、`evidence`，全部指向实际记录。

负结果特别需要观测链验证；重复同一个无效抓取不会增加反证强度。超时或达到次数预算只满足停止条件，不满足反证条件。

避免无变化重试：重试前对照旧运行的目标哈希、脚本、工具版本、参数、权限、触发条件、窗口和覆盖范围。条件未变时先说明新实验的信息增益；随机失败允许在预先声明的重复次数内重试并保留每次记录。

## 每次运行的记录

复制 [run.json](../assets/run.json)。运行前状态为 planned；实际开始后为 running；结束为 completed / failed / timed_out / cancelled；失去会话、崩溃或无法确认执行终态时用 interrupted。结束时间和退出码保留真实含义，超时或中断无退出码可写 null，并在 result 解释。interrupted 的 ended_at 记录确认中断的时间，不冒充目标进程真实退出时间。

- `command`：完整可复现命令；附 cwd、参数文件、环境差异、工具版本。敏感值用受控引用，保留复现所需的变量名和获取方式。
- `target`：目标 ID 与本次实际 SHA256；动态实验另记 PID、启动方式和配置。
- `scripts` / `artifacts`：项目相对路径与 SHA256；脚本通常指向本运行内快照。raw 与 derived 分开，派生文件增加 `parents` 和 `generated_by`。
- `observation`：触发动作、开始结束时间、覆盖范围、控制实验和失败情况。
- `result`：结果简述和局限；完成退出不等于假设成立。
- `provenance`：独立采集或派生运行及直接来源；字段与去重规则见 [来源链](acceptance-audits.md#证据来源链)。
- `state`：initial 描述实验开始时的目标/宿主状态（进程、快照、配置、缓存等与本轮有关的内容），expected_effects 写预期修改，restore_plan 写恢复命令/顺序与验证方式。开始时将 status 从 not_started 改为 pending；结束核查实际副作用并写 observed_effects，恢复后填 restored 和 verification。确实无需恢复时用 not_needed 并填写核查依据；留有进程/驱动/服务/配置未处理时保持 pending。verification 写实际核查结果并定位到 artifacts 中的日志，恢复操作不能销毁原始证据。
- 引用文本注明行号；日志注明时间及事件 ID；地址注明地址类型、模块身份与基址；截图保留触发步骤和时间。

辅助校验器要求所有已结束运行至少有产物，成功退出码默认 0；存在特殊成功码时在记录中使用 `accepted_exit_codes` 声明，并说明工具语义。

## 中断恢复

接手时先查遗留 running/interrupted：核对会话、PID 的启动时间/目标身份、调试器连接、驱动/服务、端口、挂起状态及配置差异。不能只凭 PID 仍存在就认定它还是原目标，也不能因为 agent 会话结束就认定目标已退出。

保存已有日志和部分产物及其哈希，给原运行保留 interrupted、未知退出码和局限，并在 state.recovery 填 at、assessment、next_step。没有任何输出时至少保存真实的中断/检查记录作为产物，不编造采集内容。自动终态缺失的旧 running 先评估再修正；不直接改成 completed 或重复执行有副作用的命令。

按实际影响恢复或隔离环境，记录核查与剩余事项；恢复待办留在 INDEX。需要继续实验时新建运行并引用旧运行/恢复结果，不覆盖部分输出。recovery.next_step 写具体恢复或重验动作及停止条件；尚未取得初始快照时标明未知并说明可核实范围，不能宣称已恢复到无法确认的原状态。

## 一个接管例子

历史记录称“IPC 路线证死”，但仅剩一份空日志，样本也从 B 变成 A。

- 事实：历史文字报告过未观察到数据，原运行条件缺失。无法从空文件恢复触发、窗口与观测能力。
- 决策：保留历史文字并标记证据不足；为 A 建新目标和新路线。旧结论不能直接用于 A。
- 实验：先验证捕获链能看到已知对照，再在声明窗口内触发目标动作；每次运行保留命令、脚本快照、输出和哈希。
- 判定：对照失败则 blocked；对照成功但覆盖不足则继续收集或 paused；满足既定反证条件才在明确范围内 falsified。
