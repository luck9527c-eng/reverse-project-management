# 项目布局与 INDEX

## 默认布局

```text
project/
  AGENTS.md / CLAUDE.md        复用实际 agent 入口，接入配置读取规则
  docs/agents/
    reverse-project-management.md 仓库专属配置与 consumer rules
  .agents/skills/
    reverse-project-management/ 仓库内 skill 副本与可独立运行的辅助资源
  INDEX.md                     唯一总入口：目标、现状、下一步、全部材料的导航
  re/
    targets.json               目标身份与来源
    project.json               项目验收、阶段关联审计与证据争议
    env/ENV-*.json             带时间的环境快照、安装和验证结果
    routes/R-001.json          路线的权威状态、判定标准与变更历史
    conditions/C-001.json      跨路线共用的关键前提、阻塞条件及证据版本
    docs/                     按问题或交付目的组织的结论与设计记录
    scripts/                  可维护、可复用脚本；临时脚本先随运行保存
    runs/RUN-*/
      run.json                一次运行的计划与实际记录
      scripts/                本次使用的脚本快照
      raw/                    原始输出、日志、导出、截图
      derived/                清洗、汇总、图表等派生产物
    samples/                  按需创建；只读样本或外部样本的定位信息
    tools/                    按需创建；项目私有工具、虚拟环境、版本锁定
    tmp/                      按需创建；可重新生成的缓存
```

已有仓库保留有效结构，把对应路径写入 INDEX。辅助脚本只支持上述默认布局；非默认布局应适配脚本或手动校验，不建立两套重复档案。

`init` 从共享模板复制项目配置和完整 skill 到仓库内，再建立有用的管理目录和空目标清单，不生成无内容的专题文档。agent 读取现有入口后局部接入配置指针；脚本不修改原有入口。项目目录和工具选择在 docs/agents/reverse-project-management.md 中维护，避免通过修改共享 skill 保存本地约定。

项目后续使用仓库内的 scripts/project.py、references 和 assets；将项目配置和副本提交到该仓库，使交接不依赖某台机器的全局 skill 路径。

`route.json`、`run.json`、`condition.json` 是复制后填写的模板；项目记录由 `project.json` 初始化。模板中的空值表示尚未采集，不是已验证记录。

## INDEX 的边界

“一份 INDEX”意味着一个入口。它承载当前工作集和导航，详细记录存放在各自的权威位置。把所有历史日志粘在 INDEX 会让接手成本随项目规模增长。

- **手写区**：目标与验收标准、当前判断及证据链接、当前环境快照、下一步及交接。当前判断带日期和适用目标，作为摘要指向权威来源。
- **自动导航区**：仓库内 skill、项目验收、目标清单、环境、路线、条件、运行、文档和脚本，以及待复查/重验、审计过期、证据争议与实验恢复待办。由 `index` 维护；每份正式文档和独立脚本都必须可从这里触达。运行中的原始文件通过 `run.json` 文件清单触达。
- **权威位置**：仓库专属选择在 docs/agents/reverse-project-management.md，目标身份在 targets.json，路线状态和复查记录在路线文件，共享条件状态及版本在条件文件，执行事实在运行记录，环境状态在环境快照。摘要冲突时先核对来源，再修正 INDEX。

保留一个 `<!-- RPM:NAV:START -->` / `<!-- RPM:NAV:END -->` 导航区。刷新后审阅变更；INDEX 的下一步与可领取路线依然需要 agent 判断和维护。

首次配置时在实际使用的 CLAUDE.md / AGENTS.md 中接入 INDEX 和项目配置的读取指针，按 SKILL.md 的首次配置流程选择文件并局部合并。后续 agent 沿该指针读取规则，无须把全部管理规范塞进入口文件。

## 命名与身份

- 目标 `T-001`、路线 `R-001`、运行 `RUN-20261021T093000Z-r001-01`。运行 ID 全局唯一，使用 UTC 时间或带时区的时间，加后缀避免冲突。
- 路线文件名等于路线 ID；运行目录名等于运行 ID。ID 一经引用不回收。
- 文档按稳定问题命名，如 `ipc-observation.md`；日期留在记录内。专题真正分叉或形成独立交付时再拆文档。
- 路径使用项目相对路径；外部样本在 targets.json 使用绝对路径。跨机器交接时说明挂载或获取位置。
- JSON 采用 UTF-8；时间采用带时区的 ISO 8601。平台/架构同时记录宿主和目标，避免把 64 位主机等同于 64 位目标。

targets.json 的形状：

```json
{
  "schema_version": 1,
  "targets": [
    {
      "id": "T-001",
      "path": "re/samples/app.exe",
      "sha256": "填入实际计算的64位小写十六进制哈希",
      "version": "unknown",
      "platform": "windows",
      "arch": "unknown",
      "source": "用户提供的安装包；保留包哈希与成员路径"
    }
  ]
}
```

解包成员还需记录父包目标 ID 与成员路径；运行态证据补充 PID、启动参数、用户、配置及捕获时间。对地址证据区分文件偏移、RVA、运行地址，并保存模块身份和基址。

历史样本已经丢失、SHA256 无法确认时，先把原说法、来源、缺口和恢复条件保存在 `re/docs/legacy-*.json` 或专题记录，并从 INDEX 链接。待取得真实身份后再登记到正式 targets/routes；校验器要求正式目标具有真实 SHA256，不用占位哈希或新样本的哈希代填。历史材料的保留不等于历史结论得到验证。

## 保全与版本控制

- 原始样本和 raw 产物保留字节身份；计算 SHA256。派生文件引用父文件与生成命令。
- 每次运行使用新目录。运行记录在结束前可补齐，封存后作更正记录并指向原记录，不悄悄改写结果。脚本快照与实际命令保持一致。
- 复用脚本放 re/scripts，并记录用途、依赖、输入、输出和最小调用方式。运行记录保留脚本快照或不可变提交定位及内容哈希。默认模板使用快照，避免 Git 提交不存在或工作区有未提交改动。
- 文档、路线和小型元数据进 Git。大样本、抓包、数据库、内存转储按体积和敏感性选择外部存储/LFS；保存位置、大小、哈希和取回方式。不要盲目把整个 runs/ 忽略，导致 run.json 丢失。
- 工具二进制、虚拟环境和缓存通常忽略。需要本地私有数据时按具体路径合并 .gitignore，保留已有规则。
- 清理缓存前确认重建命令；清理实验输出前确认保留策略和可取回副本。长期证据避免只保留易过期的 MCP 句柄或临时 URL。

## 交接最小内容

在 INDEX 手写区更新：当前目标与范围、最新可信发现（链接证据）、活动路线与阻塞、下一条命令及预期结果、停止条件、环境变更和清理事项。路线失败也算进展，写明减少了哪部分不确定性。

阶段结束和交接按 [验收与审计](acceptance-audits.md) 盘点全部历史路线的遗漏关联，更新审计范围、项目验收缺口、争议及遗留实验状态。INDEX 列出的待办不能被“校验通过”或新摘要掩盖。

多人或多 agent 工作时分配独立路线和运行目录；INDEX 指定一个整合者，合并前重读最新路线状态，避免状态回退和 ID 冲突。工具共享会话、目标进程和端口要说明归属。
