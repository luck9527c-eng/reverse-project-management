# 选路、单轮闭环与断点交接

## 选择可领取的工作

从 INDEX 当前工作集出发，核对目标身份、项目验收与候选路线，再执行 impact 查看条件复查和争议影响。默认推进一条路线，按以下顺序筛选：

接管资料只有口述路线清单、缺少可核验目标或原始运行时，先按 [遗留材料规则](layout.md#命名与身份) 保存原文、来源和缺口；身份可核验后再登记正式目标/路线，不把场景描述填成不完整的正式记录。若缺字段的正式记录本来就存在，保全它并披露 check 失败原因，不能编造证据或删除历史来让检查通过。

1. **先核查遗留状态。** running/interrupted 的会话、目标和副作用先按 [恢复规则](evidence-routes.md#中断恢复) 评估，保存部分输出；正常退出或可安全继续的依据明确后再安排实验。
2. **排除失效依赖。** depends_on 仅登记真正阻止开工的路线，不把发现来源误作硬依赖。历史 validated 若受 open 争议影响，当前不能作为已满足前提；依赖它的活动路线先 blocked / paused。检查本轮必需的共享条件、复查判断与工具就绪层级，按 [争议规则](acceptance-audits.md#矛盾证据与有争议结论) 处置。
3. **缩小问题。** 在剩余候选中优先选与验收相关、能区分解释、成本可控的一项。明确本轮产出后才 active；未到执行粒度的目标先做问题收敛。关闭路线按 [重开规则](evidence-routes.md#路线状态) 留下原因和原范围。

复查、恢复或争议判别本身可以成为本轮工作。其计划须明确待核实的前提，采用不依赖争议结论成立的独立对照；需要新的实验时可建独立路线。其余阻塞项保留解除条件，避免为了让所有路线可开工而批量安装工具。

**本步完成：** 能指出本轮要回答的问题、为何选它、必需前提的当前依据，以及产出/停止条件。没有可领取实验时，交付具体的恢复、补证或问题收敛动作，保留真实未完成状态。

## 把宽泛目标变成单轮任务

“把协议都弄清楚”保留为项目目标；路线 question 应能由一个短闭环减少不确定性。只细化当前能说明的问题；尚不清楚的问题留在 INDEX 的“待细化问题”，附现有材料入口及何种发现后再展开。

用现有 route 字段写任务，不另建一套 ticket 或状态：

| 字段 | 本轮须能说明 |
|---|---|
| question / hypothesis | 一个可区分的主张或待决问题，证据缺口是什么 |
| target_ids / prerequisites / depends_on / condition_ids | 目标范围，真正阻止开工的前提及其记录 |
| experiment | 最小动作、支持/反对时各会看到什么、对照与原始输出位置 |
| budget | 本轮时间/次数上限、停止条件；条件没变的重试有何信息增益 |
| evidence / history / closure | 取得的依据、决策原因与适用范围；仅在达到状态门槛时闭合 |

例如，已有资料提示某配置影响输出时，可收敛为“在同一目标身份下，两种已声明配置的输出差异是否可重复观察”。先写明哪个观察会区分解释和如何验证观测链，再取证。资料不足以指明配置或现象时，本轮产出是带来源的具体问题及最小实验计划；不补造协议事实，也不创建并未执行的 RUN。

每轮贯通 **问题 → 计划 → 原始记录 → 判定 → INDEX**。只取得一份工具导出尚未完成该闭环；可靠的负结果、明确局限或尚未解决的阻塞，也可以是真实产出。

## 断点交接

同一分析仓库的恢复点直接维护在 INDEX。按 [布局规则](layout.md#交接最小内容) 填写：

- **本轮落点：** 回答了什么、仍未知什么，链接目标、路线、RUN 与可定位原始证据。
- **下一项动作：** 工作目录、可执行命令或明确管理动作、预期产出、停止条件；先核查会话/环境的条件写在动作前。
- **不可跳过的状态：** 受争议/过期条件影响的路线、恢复/重验待办，以及最新 index / check 的实际结果和未审计范围。

接手者从入口核对当前目标哈希、路线/争议/条件版本和实际环境，再执行下一步；旧会话的“工具已连接”不证明新会话可调用。阶段交接对全部历史路线的 [关联审计](acceptance-audits.md#阶段关联审计) 仍需完成，未实际审阅的项保留 follow_up。

权威事实保留在原记录，INDEX 只给摘要和指针。跨仓库或换 agent 环境确需可携带交接文档时，按用户位置保存一份短说明，入口仍指向项目 INDEX；不复制整套日志和路线状态，不把临时交接文件变成另一份权威台账。

**交接完成：** 新会话无需猜测即可定位证据、知道先核查什么、执行下一项动作，并辨认仍未完成的部分。项目完成另按验收门槛判断。

## 从实际失败改进工作环境

本轮若反复找不到文件、误判状态或工具调用低效，阶段结束时记录实际失败证据及最小改进：导航困难修指针，重复机械错误优先复用/补充确定性检查，语义误判澄清判据或项目约定，工具低效先用现有筛选/导出。

复用仓库已有检查命令；改进落入相关脚本、规则或项目配置，INDEX 链接结果。仅当同一术语反复歧义时在已有配置/术语表定义；长期取舍在路线 history 或已有决策记录中写原因、证据与重开条件。按需拆专题，保持事实单一权威来源。项目经验先留在项目内，共享模板仅在明确维护它时修改。
